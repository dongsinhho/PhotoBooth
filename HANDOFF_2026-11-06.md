## Current product / implementation state

PhotoBooth is a free/open photobooth application aimed initially at new booth operators in Vietnam. Core is Go; the current Windows Preview UI is an isolated Wails v2.17.0 module at `tools/ui-spike/wails-v2`. Do not merge Wails into the root Go module or change the pinned toolchain without an explicit plan. The user's policy remains: booth operators may use the app commercially; operator-facing customization stays at the app/settings/frame-package layer, not arbitrary core-code modification.

Current Windows Preview supports settings persistence, local frame package management, real Logitech webcam capture, session Continue/Restart, local output retry, manual reviewed retention cleanup, internal Windows package install/update/rollback and kiosk smoke. Physical printer output is not implemented because no target model/connection/driver has been selected.

## Latest implementation: session/output identity isolation

Commit `1be3788` introduced the following:

1. **Distinct storage roots**
   - Added `internal/booth/config/paths.go`.
   - `ValidateDistinctStorageRoots` rejects identical or nested sessions/output roots after canonical path resolution.
   - Called from StoreConfig validation, Load after config-relative path resolution and Save before replacing config.
   - Retention planning and local output retry enforce the same invariant even when only one retention policy is enabled.
   - Existing Windows junction and symlink path components are resolved by the platform path resolver; Linux resolver follows symlinks through the nearest existing ancestor.

2. **Direct-child session identity**
   - `ValidateStorageChild(root, child)` requires a canonical child to remain one direct child under its assigned canonical root and preserve its expected basename.
   - Workflow validates session workspace and captures directory identity before use, before each capture and before render.
   - LocalProvider validates output session identity before/after creating the directory.
   - Output retry validates session and captures identity.
   - Re-directed session-ID junction/symlink paths fail closed.

3. **New session versus resume**
   - New workflow session claims the workspace with atomic `os.Mkdir`; if that session ID already exists, it refuses to reuse/overwrite it and does not open the camera.
   - Added explicit `workflow.Config.ResumeSession`; Continue passes it even with zero completed captures.
   - Resume only accepts a real session folder containing exactly the `captures` directory, and exactly the expected completed sequential non-empty regular capture files.
   - An empty captures directory is valid for recovery from an interruption before the first completed shot.
   - Unexpected files, stale rendered artifacts, symlinked folders/captures or mismatched capture counts are rejected.

4. **Exclusive output**
   - `LocalProvider.Execute` now uses `SaveExclusive`, as does the local retry path.
   - An already-published `photo.jpg` for the same session ID is never overwritten.

5. **Immutable Wails run configuration**
   - Wails snapshots station config, camera settings, frame path, sessions/output roots, shot count and timing under the app mutex at Start/Continue.
   - The background session uses this snapshot rather than reading mutable App config fields.
   - Continue is blocked during settings save and when the saved profile has a load/validation warning.

## Recommended next implementation step (Windows-only; no Linux prerequisite)

Implement and test **crash/restart recovery for an interrupted session**:

1. Define a conservative discovery/read-only inspection contract for incomplete session directories. Do not auto-resume, delete or rewrite data during discovery.
2. Persist enough per-session metadata to distinguish preflight, capturing, rendered and output-finalized phases, plus expected shot count/frame/config version and timestamps. Prefer an atomic manifest update; avoid assuming folder existence means a valid resumable session.
3. On app startup, inspect only the configured sessions root, reject symlink/junction redirects and unknown layouts, and surface recoverable sessions to the operator without starting the camera.
4. Require explicit operator choice to Continue, Restart as a new ID, export/inspect, or dismiss. Continue must validate every capture and match the manifest; stale/ambiguous sessions remain untouched.
5. Make phase transitions and output publication crash-safe. Do not delete original capture/rendered files until a separate explicit retention review.
6. Add failure-injection tests around process interruption boundaries using temp directories; no physical camera required.
7. Update ROADMAP and handoff; run root/Wails tests, vet, Windows build and Linux compile-only checks. Keep all Linux runtime, USB, soak, image-quality and printer gates pending.

Be careful: do not infer resume eligibility from a directory name or a non-empty captures folder alone. Treat missing/corrupt manifest or unexpected files as recoverable-for-inspection but not automatically resumable.
