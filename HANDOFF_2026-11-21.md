## Accepted production direction

- Windows 11 x64 and Ubuntu 24.04 LTS x86_64 are parallel first production targets.
- RAM targets: Windows 8 GiB; Linux 4 GiB. These are unvalidated target minima, not certified specifications.
- macOS is a possible future platform only.
- UI has Customer Mode and authenticated Operator Mode.
- Customer Mode is fullscreen, touch-first, hides all settings/admin actions and is the default on each launch.
- Operator Mode exposes settings/maintenance after authentication. The operator can return to Customer Mode or authenticate and exit the app to the OS desktop.
- The operator logs into the OS first; the app auto-starts in that interactive session and enters Customer Mode.
- Installer-only distribution; no portable end-user build. First package targets: signed per-user Windows installer and Ubuntu .deb.
- App may notify about updates; operator must approve installation. No silent/background installation.
- Free/local capture, render and save must work offline.
- Future payment direction supports provider-verified VietQR and static QR with authenticated local operator confirmation. The latter is a manual operator decision, not verified bank settlement.
- Share the Go core; separate per-OS UIs are acceptable when necessary for performance/native integration.
- Wails v2.17 remains an incumbent prototype/benchmark candidate, not unconditionally approved for production.
- Remote operator configuration is a distinct future capability. Do not expand or reopen the paused SMB Remote administration feature.

## Important evidence and limitations

- Current Wails module: v2.17.0 in the isolated Go 1.25.0 module; root Go core remains Go 1.24.8.
- Linux UI evidence is WSL2 Ubuntu 26.04.1, not native Ubuntu 24.04. The selected production target is Ubuntu 24.04 LTS.
- A prior 10-minute Wails Preview soak on the 16 GiB ShinPc host recorded a process-tree private-byte peak of about 1.29 GiB. This does not validate either the Windows 8 GiB or Linux 4 GiB target.
- No native Ubuntu 24.04 kiosk/installer acceptance; no Linux physical camera or printer runtime acceptance.
- Current Windows release flow creates internal-alpha ZIP packages and has signing-verification groundwork. There is no genuine production publisher certificate/trust pin or final user-facing signed installer.
- No Operator Mode authentication flow, authenticated exit-to-desktop UI, login auto-start implementation, update notification service, VietQR integration, or local payment-confirmation channel was implemented by this checkpoint.
