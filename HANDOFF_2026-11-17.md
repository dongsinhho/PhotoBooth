## Stage 2 SMB default-off policy and helper — 2026-11-16

This supersedes the older next-step wording above that left the deployed SMB policy undecided.

**Accepted product decision:** Windows booth deployments should have SMB Server (LanmanServer) and workstation administrative shares disabled by default. SMB remote administration is a separate explicit operator-maintenance action, never a guest-photo delivery path.

**Opt-in contract:** invoke a package-owned PowerShell helper through Windows UAC. Enable is limited to one physical adapter already classified Private by Windows and literal RFC1918 remote IPv4 source addresses explicitly supplied by the operator. It opens inbound TCP 445 only on the selected local address and Private profile, while keeping the PhotoBooth TCP 445 Block rule active on Public and Domain profiles. Legacy NetBIOS TCP 137/139 and UDP 137/138 stay blocked. It does not enable SMB1/guest access, change ACLs, create guest shares, change a Public network to Private, or configure router port forwarding. Disable removes only the PhotoBooth Allow rule, installs PhotoBooth-owned inbound blocks, sets AutoShareWks=0, and stops/disables LanmanServer. Both state-changing actions abort on active sessions, running service dependents, custom SMB shares, or conflicting SMB rules rather than force changes.

**Prototype created:**
- docs/adr/0031-opt-in-windows-smb-administration.md records the accepted policy and remaining validation gates.
- tools/self-service/manage-smb-remote-admin.ps1 provides Status, Enable, and Disable.

## 2026-11-18 continuation — Remote administration use case and scope freeze

The product owner tested the Remote administration feature successfully and decided to pause further work on it. Treat the current feature scope as accepted; do not continue the remaining hardening/qualification checklist by default.

### Use case

Remote administration is an optional operator/maintainer convenience for authorized remote maintenance of a Windows Booth. From a trusted maintenance computer, an operator can use authenticated SMB administrative shares (`C$`, `ADMIN$`, `IPC$`) for permitted tasks such as retrieving diagnostic logs, inspecting or updating application/configuration files, and compatible Windows administration operations. Access remains governed by Windows credentials, share permissions and NTFS permissions.

It is not a guest-facing file share, guest photo/session delivery path, anonymous access feature, or replacement for a future session-scoped LAN delivery design. If remote maintenance is not needed, keep it disabled.

### Accepted scope and test policy

- Keep SMB Server default-off on fresh installs.
- Enable remains explicit operator opt-in through the existing UI/helper/UAC flow, with an already-Private selected physical adapter and explicit trusted RFC1918 remote source IP allowlist.
- Accepted happy path: Enable → authenticate/list administrative shares from the allowlisted maintenance host → Disable → verify default-off state restored. The tested ShinPc/Unix path passed and was accepted by the product owner.
- Happy path is sufficient for the current Preview scope. Do not schedule additional non-allowlisted-source, reboot-persistence, IPv6/other-interface, failure/rollback, NetBIOS UDP or disposable-VM tests unless a concrete deployment requirement or reproducible issue reopens the scope.
